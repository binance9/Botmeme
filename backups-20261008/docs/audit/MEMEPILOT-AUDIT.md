## Five specialist perspectives (Codex internal simulation, not five external agents)

- Architecture: keep one event log and typed boundaries; reject importing the old Runtime/PaperEngine whole.
- Data: retain source hashes/freshness; require chain identity, ordered observations and unknown-data states; no boolean-only proofs.
- Quant/accounting: fixed-point cash/fees and position-level metrics; chronological replay/OOS; no profit claim from incomplete cost basis.
- Security: no private-wallet material, signer, live endpoints or tunnels; separate provider credentials from public connection state.
- Acceptance/UI: freeze current layout/theme; add only bottom-left collapsed wallet. Verify actual runtime; unit fixtures never replace live evidence.

Tradeoff: copying old runtime is faster but preserves forbidden coupling/signers. Rewriting everything discards tested accounting/source ideas. Selected algorithm PORT plus boundary REWRITE is the smallest safe route.
